# 写真ベース会計報告スキル

## このスキルが解決する課題

イベントや研究会の会計担当者は、手元にレシート・領収書の写真と参加者リストがあるだけで、
それをもとに収支報告書を作る必要がある。画像からの読み取りは完璧にはならないため、
「まずCSVで出して人間が直す」というステップが不可欠。

## 3段階フロー

### Stage 1: データ抽出（画像→CSV）

1. フォルダ内の画像ファイルを特定する
2. HEIC形式の場合はJPEGに変換する（pillow-heif + Pillow を使用）
   ```python
   from pillow_heif import register_heif_opener
   from PIL import Image, ImageOps
   register_heif_opener()
   img = Image.open("input.HEIC")
   img = ImageOps.exif_transpose(img)  # EXIF回転を適用
   img.save("output.jpg", "JPEG", quality=90)
   ```
3. 変換後の画像を Read ツールで読み込み、**上下の向きを目視確認する**
   - EXIF transpose だけでは正しくならない場合がある（特にスマホで撮影した書類写真）
   - 文字が正位置で読めるか確認し、必要に応じて90/180/270度回転する
   - 全4方向のテスト画像を生成して確認するのが確実：
     ```python
     for angle in [0, 90, 180, 270]:
         rotated = img.rotate(angle, expand=True)
         rotated.save(f"test_rot{angle}.jpg")
     ```
   - 正しい向きが確定したら、テスト画像は削除する
4. PDFがあれば参加者リスト等として読み込む
5. 読み取れた情報をCSVに書き出す

#### CSV出力フォーマット

```csv
区分,項目,摘要,金額,支払方法,状態,画像出典,備考
収入,参加費,2000円×16名,32000,現金,済,,全員徴収済
支出,懇親会,レストランXX,15000,現金,済,IMG_001.jpg,
支出,会議室,○○会館,0,請求書,未精算,IMG_002.jpg,金額読取不可
```

フィールド定義：
- **区分**: 「収入」または「支出」
- **項目**: 費目（参加費、補助金、懇親会、交通費、備品、会議室 など）
- **摘要**: 具体的な内容（店名、人数計算式、相手先など）
- **金額**: 半角数字。読み取れない場合は空欄にする（0にしない）
- **支払方法**: 現金 / 振込 / 請求書 / カード など
- **状態**: 済 / 未精算
- **画像出典**: 元画像のファイル名
- **備考**: 「要確認」「金額読取不可」など。確信が持てない項目には必ず付ける

#### 画像読み取りの心得

- 手書きの領収書は金額の桁を間違えやすい。¥5,000 と ¥50,000 など
- レシートの合計と明細を両方読み、矛盾があれば備考に書く
- 読み取れない項目は無理に推測せず空欄＋「金額読取不可」とする
- 同じ画像に複数のレシートが写っている場合がある。1枚ずつ行を分ける

#### 参加者数の数え方

- 参加者名簿の行数を正確に数えること。表の下部に書かれた数字は特定日の出席者数であり、名簿の総人数とは異なる場合がある
- 複数日程のイベントでは、日ごとの出席状況（○×）と名簿の総登録人数を区別する
- 「参加費×人数」の計算は、名簿の人数を正確に数えたうえでユーザーにも確認する

### Stage 2: ユーザー確認

CSVを書き出したら、ユーザーに以下を依頼する：
- 金額の確認・修正
- 空欄の補完
- 項目名・摘要の修正
- 不要行の削除

ユーザーが修正済みCSVを提示するか、口頭で修正指示をくれるまで、
Stage 3 に進まないこと。

### Stage 3: 報告書作成（CSV→Word＋PDF）

ユーザー確認済みのデータから報告書を生成する。
docxスキルを使用してWord文書を作成し、docx2pdfでPDFに変換する。

#### PDF変換

Windows環境では docx2pdf（Word COM経由）を使用する：
```python
from docx2pdf import convert
convert("input.docx", "output.pdf")
```
LibreOfficeのsoffice.pyスクリプトはWindows（AF_UNIX非対応）では動作しない。

#### 報告書の構成

```
タイトル: ○○ 会計報告書（簡易版）
日付: YYYY年MM月DD日
作成者: （ユーザーに確認）

1. 収支概要
   出金額（元手）、現金収入合計、現金支出合計、現金残高を表形式で
   ※注釈で未精算・未入金の項目を記載

2. 収入明細（表）
   | 項目 | 摘要 | 支払方法 | 金額 |

3. 支出明細（表）
   | 項目 | 摘要 | 支払方法 | 状態 | 金額 |
   ※交通費等は個人名を出さず「○○円 × N名」と集約する
   ※交通費補助基準がある場合はその根拠も記載する

4. 交通費補助の基準（該当する場合）
   支給基準とその考え方を箇条書きで

5. 未精算・未入金事項
   【未精算（支出）】と【未入金（収入）】に分けて記載

6. 証憑画像
   レシート・領収書の写真を正しい向きで添付
```

#### 交通費の記載ルール

- 個人名は記載しない（プライバシー配慮）
- 金額ランク別に「5,000円 × 4名」のように集約する
- 補助基準（遠方/宿泊、県外、市内等）があれば別セクションで説明する

#### 未入金の扱い

- 団体・支部からの補助金等で未入金のものは「未入金（収入）」として金額とともに明記する
- 現金残高には含めない

#### 現金残高の計算ロジック

ユーザーが「○○円を出金した」と言った場合、それが運営資金の元手。

```
現金残高 = 出金額 + 現金収入 - 現金支出
```

- 現金収入: 支払方法が「現金」の収入行の合計
- 現金支出: 支払方法が「現金」かつ状態が「済」の支出行の合計
- 振込・請求書の収支は現金残高に含めない（別途記載）

## ファイル命名

katochan-file-rules スキルに従う：
```
YYYYMMDD_案件名_会計報告_vN.docx
YYYYMMDD_案件名_会計データ_vN.csv
```

## チェックリスト

報告書を最終出力する前に確認：
- [ ] 収入合計と支出合計の差引が正しいか
- [ ] 現金残高の計算が合っているか
- [ ] 未精算事項が漏れなく記載されているか
- [ ] 未入金事項が漏れなく記載されているか
- [ ] 金額はすべて半角数字か
- [ ] ユーザーがCSVを確認済みか
- [ ] 証憑画像の上下が正しいか（文字が正位置で読めるか）
- [ ] 交通費等に個人名が出ていないか
- [ ] 過去バージョンや中間ファイルを削除したか
